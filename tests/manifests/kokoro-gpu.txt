# Kokoro-82M port, the model ON THE DEVICE — `pixi run -e nvidia test-kokoro-gpu`
# (or -e apple)
#
# The companion to `kokoro-ref.txt`, same converted checkpoint and reference
# dumps (see its header for how to produce them). The weights are 330 MB: it
# fits beside anything, but keep one GPU model process at a time on a 16 GB
# machine.

# `noeira/audio/kokoro/device.mojo` against hexgrad's KModel again, not against
# our CPU path: PL-BERT, the duration encoder and LSTM, the frames per phoneme
# (EQUAL), the text encoder, pitch and energy, the decoder's blocks (1e-4), and
# the generator fed the reference's own source spectrum down to `conv_post` and
# the waveform (2e-4; see `kokoro-ref.txt` for why the harmonic source is gated
# apart). Three injected defects (the style row's halves exchanged, one frame
# moved between phonemes, the source spectrum one frame late). Prints the
# per-stage and end-to-end timings.
tests/audio/test_kokoro_gpu.mojo

# ⚠ The default build is full fp32 on every target. `-D KOKORO_TF32=1` runs the
# generator's convolutions in TF32 on NVIDIA (82 against 135 ms on the Orin) and
# the gate then holds the waveform to 1e-2 instead of 2e-4 — a build-time
# variant (`mojo run -D` can be stale):
#
#   pixi run -e nvidia mojo build -D KOKORO_TF32=1 -I . tests/audio/test_kokoro_gpu.mojo \
#     -o build/test_kokoro_gpu_tf32 && ./build/test_kokoro_gpu_tf32
#
# In the TF32 build the vocoder's convolutions go through cuDNN's implicit GEMM
# (`noeira/audio/kokoro/cudnn_conv.mojo`; generator 82 -> 55 ms on the Orin).
# `KOKORO_IM2COL=1` in the environment runs the same binary on im2col + cuBLAS,
# for an A/B; both pass the TF32 bounds.
#
# On the Orin: `pixi run -e jetson build-jetson ...` (adds `--target-accelerator
# sm_87`), and run the binary with JetPack's cuBLAS AND cuDNN first on the loader
# path. The jetson env's own cuDNN 9.10.2 fails every convolution on the Orin
# (EXECUTION_FAILED; the model then falls back to im2col and says so), and
# /usr/lib/aarch64-linux-gnu cannot go first as a whole, so link JetPack's
# libcudnn*.so.9 into a directory of their own:
#
#   mkdir -p ~/cudnn-jetpack && ln -sf /usr/lib/aarch64-linux-gnu/libcudnn*.so.9 ~/cudnn-jetpack/
#   LD_LIBRARY_PATH=~/cudnn-jetpack:/usr/local/cuda/lib64:$LD_LIBRARY_PATH ./build/test_kokoro_gpu_tf32
