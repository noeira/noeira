# Vision manifest — `bash scripts/run_tests.sh tests/manifests/vision.txt`
#
# ⚠ NOT part of `test-smoke`, for ONE reason: it needs a build artifact.
# `pixi run build-opencv` produces `noeira/vision/opencv/libmojo_cv.dylib`,
# which is gitignored like every other shim, so on a fresh checkout the gate
# would SKIP rather than fail — and a skip that reports success is the vacuity
# failure this tree keeps recording. Keep it a tier you run deliberately.
#
# Prerequisites:
#   pixi run build-opencv
#
# The fixtures ARE committed (3 KB of .mp4, 117 KB of pinned decode), so unlike
# the ACT manifest this needs no reference tree, no torch and no camera. To
# regenerate them after an intentional change:
#   pixi run python tools/vision/make_capture_fixture.py    # the video
#   pixi run python tools/vision/make_marker_fixture.py     # the marker scene
#   pixi run python tools/vision/make_charuco_fixture.py    # 11 board views
#   pixi run python tools/vision/dump_cv_reference.py       # cv2's answers
#
# ⚠⚠ THE ASSERTIONS ARE EXACT BIT EQUALITY, NOT A TOLERANCE. Both sides call
# the SAME dylib, so a difference is a marshalling bug and never a numerical
# one. If a future change here needs a tolerance, the change is wrong.

# ALL SIX GROUPS of docs/OPENCV_SHIM_SCOPE.md: A (version, error string, thread
# count), B (capture + the one BGR HWC -> RGB CHW conversion), C (imread, ArUco
# detection), D (solvePnP, Rodrigues), E (ChArUco, calibrateCamera) and F (the
# 3x3 SVD the extrinsics fit needs). 36 checks.
tests/vision/test_opencv_shim.mojo
# The camera -> ACT tensor path, against PIL BILINEAR. ⚠ A DIFFERENT KIND OF
# EXACTNESS than the line above: nothing is shared with PIL here, so bit
# equality is a claim about having REPRODUCED libImaging/Resample.c rather than
# about having called it. Regenerate its fixture with
#   pixi run python tools/vision/make_resize_fixture.py
tests/vision/test_act_preprocess.mojo
# The two PIL-bilinear implementations against EACH OTHER, at the SO-101 rig's
# own geometry (640x480 -> 320x240). Both are gated against PIL above and in
# tests/io/test_image_resize.mojo — but the ACT deployment trains through one
# and infers through the other, and no gate could see that boundary. Needs no
# shim, no camera and no PIL.
tests/vision/test_resize_deploy_vs_import.mojo
# The camera -> robot-base rigid fit (Kabsch through the shim's `svd_3x3`),
# which had no caller but its own test until this landed. ⚠ A THIRD KIND OF
# EXACTNESS: the transform is synthesised here, so the truth is exact and the
# claim is about the SOLVER, not about a rig. The case it exists for is the
# REFLECTION — `R = V Ut` maximises over ORTHOGONAL matrices, so a mirror
# world fits BETTER than any rotation and reports rms 0.000 mm. Needs the
# shim; needs no camera, no arm and no fixture.
tests/vision/test_extrinsics_kabsch.mojo
# The calibration FILE — identity, image size, intrinsics, optional extrinsics.
# ⚠ MOST OF ITS CHECKS ARE REFUSALS, and that is the point: every format
# round-trips, so a format is judged by what it REJECTS. A calibration measured
# at 1280x720 handed to a 640x480 frame is off by exactly 2x in fx AND cx,
# looks entirely reasonable, and was undetectable in the six-float file this
# replaces. Needs no shim, no camera, no fixture.
tests/vision/test_calib_file.mojo
# The fisheye -> sim-pinhole path (`vision/fisheye.mojo`, `fisheye_calib.mojo`):
# the Mojo lens model and undistortion map against cv::fisheye, the target
# pinhole against the TRACER's own camera ray, a synthetic 170-degree
# calibration recovered (with a control that the lens terms matter and a check
# that the bootstrap spread tracks the true error), the remap. ⚠ NOT bit
# equality like the entries above: the model is a PORT (float tolerances, each
# stated in the file), and the calibration is a fit.
tests/vision/test_fisheye.mojo
# The extrinsics path for the rig's fisheye cameras: marker corners
# undistorted through the lens then a K=I solve_pnp (vs raw pixels as a
# pinhole, the control), and the measured-vs-sim comparison — the tower's own
# `overhead_cam` must come back as the asset's `<camera pos xyaxes>` at 0 mm
# / 0 deg, and a known perturbation as itself.
tests/vision/test_extrinsics_fisheye.mojo
# The marker offset solved with the camera (`fit_rigid_with_offset`): exact
# noise-free, within 3 mm / 0.5 deg at 1 mm of marker noise, a zero-offset fit
# on the same data > 20 mm off (the control), and a wrist turned about ONE
# axis refused rather than answered.
tests/vision/test_extrinsics_offset.mojo
# The tabletop pose estimator (`vision/tabletop_pose.mojo`: colour mask ->
# component -> fit of the known prism), on frames drawn by an EXACT ray caster
# that shares only the lens with it, through the sim pinhole AND the rig's
# measured fisheye: brick <= 1.5 mm / 2 deg, bowl <= 2 mm; a control that the
# lens matters (the bowl read as a pinhole is > 10 mm off); occlusion lowers
# `coverage`; a brick-coloured box outside the ROI is not taken. Needs no shim.
tests/vision/test_tabletop_pose.mojo
